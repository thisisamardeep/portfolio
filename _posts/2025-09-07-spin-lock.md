Spin locks are the bread-and-butter of concurrent programming, enabling threads to synchronize access to shared resources.
There any many variations of spin locks.However, the classic spin lock can cause significant contention and cache-coherency traffic, 
especially as the number of threads grows. Enter the **CLH (Craig, Landin, and Hagersten) Spin Lock**—a scalable, FIFO, and cache-friendly
lock that can greatly improve performance in multi-core environments.Please note there are atleast 10 different ways to write a fifo spin lock.
Below is just one of the many ways you can do this.This sample implementation takes care of the starvation problem.

## How Does It Work?

Let’s break it down:

1. Thread wants the lock:
    Marks its node as `locked = true`.
    Atomically swaps its node into the tail of the queue, receiving a pointer to its predecessor’s node.

2. Spinning:
   The thread waits (“spins”) until its predecessor sets `locked = false`.

3. Releasing the lock:
    The thread sets its own node’s `locked` flag to `false`.
    For reuse, the thread recycles its node by swapping with its predecessor node for the next round.

4. When NOT to use this lock:
   Suppose you have 64 core machine and in your application you may have more threads than cores then you go
   into undefined world of this lock.More threads than size of arrays will cause the array to have false flags and you might get into infinite loop
   or deadlocks.Please use this only if you know what you are doing and the size of array should be more that maximum possible number of
   active threads.Locks , atomics and coroutines are very powerful if used  correctly but they can lead to some very subtle and hard to find bugs even for a
   seasoned C++ developer  if not used correctly.
   


This mechanism ensures:
- Scalability: Only two threads contend for the same cache line at any time.
- Fairness: Threads acquire the lock in FIFO order.
